## The question

**Do Plan’s five “buttons” belong next to free-drafting?**

1. **They look like a form.** Five CRects on the Plan well read as “tap to edit this field.” Law is the opposite: Plan is live CURRENT, read-only as the ticket. Edit lives on Draft, whole file, NOT ACTIVE.
2. **They are a table of contents, not actions.** Peeking Objective vs Next vs Keep is ticket-header grammar. Useful if the phosphor is truncated (~120). Harmful if Mum thinks she just changed the plan without Yes.
3. **Free-drafting does not use those keys.** The writer is one `EditText` on `PROPOSE-CURRENT.md`. There is no per-field schema editor on first sit (ALPHA/BETA/GAMMA recanted). Opening the writer from a Plan key would mix **live law** with **suggestion**.
4. **Quiet Next room already recanted.** After Yes the same well becomes feet, not a fifth bank. Adding a Plan-key editor would be a new room in the same hole.
