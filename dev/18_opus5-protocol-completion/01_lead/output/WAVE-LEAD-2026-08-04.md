# 1. Executive lead brief

Priority order is therefore: (a) make the lifecycle cyclic with a thin re-SELECT, (b) make it *showable* in one command against a sandbox root, (c) make Grok Build's out-of-band edits **visible** rather than blocked, (d) only then write the Lab design and the honesty/release text.

# 2. Ordered waves

## Wave 0 — Close the lifecycle (thin re-SELECT) + sandbox root

**Goal:** CURRENT can advance to a new Next after APPROVED without editing the file by hand and without a schema change; every `aether` command can be pointed at a throwaway root.

**Files**
- `aether` (add `next` subcommand; add `AETHER_ROOT` resolution; extend `usage`)
- `tests/run.sh` (+ `tests/cases/` if that layout exists)
- `docs/PROTOCOL-TEST-SURFACE.md`
- `AGENTS.md` (one line: after approve, agents must `aether next <action-id>`, never hand-edit Next)

**Commands (discovery first — do not guess the schema)**
```sh
cd /mnt/kingston-nixos-sync/opt/mechanicall-os
git status --short && git rev-parse --abbrev-ref HEAD
grep -n 'Next\|Gate\|Now\|APPROV\|SELECT' aether | head -60
grep -n 'CURRENT.md\|ROOT\|events' aether | head -40
sed -n '1,60p' CURRENT.md
sh tests/run.sh
```

**Implementation contract**
1. `AETHER_ROOT="${AETHER_ROOT:-$PWD}"` resolved once at top; every read/write of `CURRENT.md` and the event ledger goes through it. No other behaviour change.
2. `./aether next <action-id>`:
   - refuses (exit 2) if gate state is not `APPROVED`/terminal — message: `refuse: current action not approved; approve or reject first`
   - refuses (exit 2) if `<action-id>` is missing or equals the current Next — `refuse: next unchanged`
   - on success: rewrites only the existing Next field + resets the gate field to its initial SELECT/PROPOSED value, appends event `NEXT_SELECTED <old> -> <new>`, exit 0
   - `--reason "<text>"` optional, recorded in the event.
3. `./aether current validate` must accept the post-`next` file (this is the real regression risk).

**Acceptance**
- `AETHER_ROOT=$(mktemp -d)` copy of CURRENT.md: `preflight` → `approve` → `next demo-two` → `preflight` all exit 0; second `next demo-two` exits 2.
- `./aether next foo` before approve exits 2 and does **not** modify the file (`git diff --exit-code CURRENT.md`).
- New tests: `current validate` on (i) good file, (ii) file with missing Next, (iii) file after `next`. `sh tests/run.sh` green.
- Real root `CURRENT.md` unchanged by the whole wave (`git diff --stat`).

## Wave 1 — `./aether demo`: refuse + allow + approve + re-SELECT in one command

**Goal:** one non-interactive command that proves the authority protocol to a human or a peer model, in a temp dir, with readable narration.

**Files**
- `scripts/protocol-demo.sh` (POSIX sh, `set -eu`)
- `aether` (`demo` subcommand → execs the script)
- `docs/PROTOCOL-TEST-SURFACE.md` (map each demo step to the claim it proves)
- `tests/` (assert demo exit 0 + expected markers)

**Commands**
```sh
mkdir -p scripts && $EDITOR scripts/protocol-demo.sh
chmod +x scripts/protocol-demo.sh
./aether demo
./aether demo --quiet; echo "exit=$?"
sh tests/run.sh
```

**Script contract**
- `WORK=$(mktemp -d)`; trap cleanup; seed a minimal fixture CURRENT.md from `docs/` or generate inline; `export AETHER_ROOT="$WORK"`.
- Steps, each printing `STEP n/6` + the command + the verdict:
  1. **REFUSE** — `preflight` on an action-id that is not Next → nonzero, quoted refusal.
  2. **ALLOW** — `preflight` on the real Next → zero.
  3. **NO SILENT PASS** — attempt `approve` with no human token/flag → refused (silence ≠ permission).
  4. **APPROVE** — explicit human approval → gate APPROVED, event written.
  5. **RE-SELECT** — `next <second-action>` → gate reset, event written.
  6. **LEDGER** — `events` tail showing the full chain.
- Ends with `DEMO OK` on success; any deviation is a hard failure.

**Acceptance**
- `./aether demo` exits 0, prints `DEMO OK`, leaves no files outside the temp dir (`git status --short` clean after).
- Steps 1 and 3 visibly fail-closed; a reader can see the refusal text.
- Test asserts exit 0 and presence of `REFUSE`, `APPROVED`, `NEXT_SELECTED`, `DEMO OK`.

## Wave 2 — Grok interference observability (report, don't block)

**Goal:** because the operator's primary TUI is Grok Build and it does not auto-preflight, the protocol must *notice* out-of-band mutation and say so — at session start and on demand.

**Files**
- `aether` (`drift`, `brief` subcommands)
- `docs/GROK-SEAT.md` (new: how the Grok seat coexists with the protocol)
- `.grok/` or existing hook dir — **optional, opt-in only** SessionStart snippet, disabled by default
- `AGENTS.md`, `docs/PROTOCOL-TEST-SURFACE.md`

**Commands**
```sh
grep -rn 'SessionStart\|hook' docs .grok 2>/dev/null | head
./aether brief
./aether drift; echo "exit=$?"
```

**Contract**
- `./aether brief` — ≤12 lines, agent-readable: current Next action-id, gate state, whether preflight would pass, last 3 events, drift summary. This is the string an external TUI pastes at SessionStart. Exit always 0.
- `./aether drift` — uses git as the witness (no new state file): if the working tree has modifications while gate is **not** in an approved/in-flight state for those paths, print `DRIFT: <path> edited outside protocol` per file; exit 0 when clean, 1 when drift found. Never modifies anything.
- `docs/GROK-SEAT.md`: explicit statement — *the protocol observes Grok Build, it does not gate it; the human gate is the authority, drift is a report.* Include the paste-at-start snippet and the "after approve, run `aether next`" rule.
- Any hook is opt-in, documented, and non-blocking (advisory print only).

**Acceptance**
- Touch a tracked file in a sandbox root → `drift` names it, exit 1; revert → exit 0.
- `brief` runs with a stale/hand-edited CURRENT without crashing (degrades to a warning line).
- No command in this wave writes to `CURRENT.md`.
- Tests cover drift-clean and drift-dirty.

# 4. Risks / anti-patterns

- **Schema creep.** Any temptation to add a Next-history array or new CURRENT type = stop. Re-SELECT reuses existing fields; history lives in the event ledger. Human has not opened v2.
- **Demo mutating reality.** A demo that writes the repo's real `CURRENT.md` destroys trust in the gate. `AETHER_ROOT` + `mktemp -d` is a hard precondition for Wave 1; do not ship the demo before Wave 0 isolation is proven.
- **Enforcement creep on the Grok seat.** A blocking SessionStart hook makes the operator's primary TUI hostile. Drift is a *report*, exit code 1, advisory only, opt-in hook.
- **`next` as a silent approve.** If `next` can run while unapproved, the gate is decorative. Refuse-before-approve is the single most important test in the sprint.
- **Bashisms.** `./aether` is POSIX sh — no `[[`, arrays, `local -n`, `mapfile`, `${var,,}`. Test with `sh`, not `bash`.
- **Chrome over protocol.** No web Lab app, no Session seats work, no Outlook client, no CURRENT dashboard this sprint. Wave 3 is a doc plus one read-only command.
- **Honesty drift.** "Not multi-user" is a false claim; "capped ≤5-seat hosted lab" is the true one. Grep before publishing anything.
- **Publishing without a human.** Release notes stay `STATUS: DRAFT`. No tag, no push to a public surface, no announcement. Silence from the human is never permission.
- **Client One dependency.** They're idle; nothing in these waves may block on them.
- **Secrets.** Demo fixtures use `demo-one`/`demo-two` action-ids only — no tenant names, no tokens, no domains beyond what's already public.
